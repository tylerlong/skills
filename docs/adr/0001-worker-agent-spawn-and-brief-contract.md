# Worker Agent spawn-and-brief contract

When `implement-in-parallel` spawns a Worker Agent, each worker must be created able to spawn its own sub-agents and briefed with an exact template naming the `implement-in-parallel` skill and its Child Ticket — never a transcription or summary of any skill's instructions; the worker reads the skill tree itself. The Primary Agent reads no coding skills, so spawning a worker as a leaf (unable to delegate) or handing it secondhand skill text both silently break the chain: the two independent reviewers required by `implement` → `code-review` never run, and the worker depends on lossy content. Both failure modes were observed in production before this contract; the trade-off (orchestrator-capable, tersely-briefed workers that self-load skills) is deliberate and easy to "fix" back into the broken shape, so it is recorded here.
